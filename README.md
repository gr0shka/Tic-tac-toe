# Tic-Tac-Toe Game Service

RESTful API сервис для игры в «Крестики-нолики» с поддержкой двух режимов игры: против **непобедимого ИИ на базе алгоритма Minimax** (`player_vs_bot`) и **многопользовательского режима между игроками** (`player_vs_player`).

Сервис спроектирован в соответствии с принципами **чистой архитектуры (Clean Architecture / DDD)**, использует **PostgreSQL** для персистентного хранения данных, **Uber Fx** для сборки зависимостей и **HTTP Basic Auth** для аутентификации пользователей.

---

## ✨ Ключевые возможности

- **Два режима игры**:
  - `player_vs_bot`: одиночная игра против алгоритма Minimax с оптимизацией по глубине дерева решений (Depth Penalization).
  - `player_vs_player`: игра между двумя реальными игроками (создание открытого лобби, получение списка ожидающих игр, присоединение к игре).
- **Пользователи и безопасность**: Регистрация пользователей, хеширование паролей через `bcrypt`, аутентификация через HTTP Basic Auth middleware.
- **Персистентность в PostgreSQL**: Хранение игровых сессий и пользователей в реляционной БД с использованием `jackc/pgx/v5` (`pgxpool`) и версионированием схемы через миграции `goose`.
- **Чистая архитектура (DDD)**: Полная изоляция доменной бизнес-логики от деталей транспорта и базы данных с соблюдением принципа инверсии зависимостей (DIP).
- **Внедрение зависимостей (DI)**: Построение графа зависимостей и Graceful Shutdown HTTP-сервера через [Uber Fx](https://github.com/uber-go/fx).
- **Строгая серверная валидация**: Проверка очерёдности ходов, запрет на модификацию ранее занятых клеток и множественные ходы за один раунд.
- **Контейнеризация**: Мультистейдж [`Dockerfile`](Dockerfile) (минимальный образ на базе Alpine с непривилегированным пользователем) и [`docker-compose.yml`](docker-compose.yml) для развёртывания сервиса вместе с БД.
- **Интерактивный веб-клиент**: Встроенный интерфейс ([`tic-tac-toe.html`](tic-tac-toe.html)) для визуального и функционального тестирования API прямо из браузера.

## 🏛️ Архитектура проекта

Структура репозитория организована по принципам Clean Architecture:

```text
├── cmd/
│   └── main.go                         # Точка входа в сервис (fx.New().Run())
├── internal/
│   ├── config/                         # Конфигурация приложения и чтение .env
│   ├── di/                             # Сборка графа зависимостей (Uber Fx) и запуск HTTP-сервера
│   ├── domain/                         # Слой бизнес-сущностей и доменных правил (чистый Go)
│   │   ├── game/                       # Сущности GameBoard, CurrentGame, Player, доменные ошибки
│   │   ├── user/                       # Сущность User и валидация
│   │   └── service/                    # Доменные сервисы: расчет ходов (Minimax), валидация доски
│   ├── usecase/                        # Слой прикладных сценариев (оркестрация)
│   │   ├── app/                        # AppService: создание игр, ходы, join, завершение игры
│   │   └── user/                       # UserService: регистрация, аутентификация, профиль
│   ├── repository/                     # Инфраструктурный слой доступа к данным
│   │   ├── postgres/                   # Реализация репозиториев на базе PostgreSQL (pgx/v5)
│   │   │   ├── game/                   # Репозиторий текущих игр и DTO-мапперы
│   │   │   └── user/                   # Репозиторий пользователей
│   │   └── testutil/                   # Вспомогательные утилиты для интеграционных тестов БД
│   └── transport/                      # Слой доставки
│       └── http/                       # HTTP-хэндлеры, DTO, CORS и Basic Auth middleware
├── migration/                          # SQL-миграции базы данных (Goose)
├── Dockerfile                          # Мультистейдж сборка Docker
├── docker-compose.yml                  # Сервисы приложения и PostgreSQL
├── Makefile                            # Команды миграций, тестов и сборки
├── tic-tac-toe.html                    # Интерактивный веб-клиент для тестирования
└── .env.scheme                         # Шаблон переменных окружения
```

## 🚀 Быстрый старт

### 1. Настройка переменных окружения

Создайте файл `.env` на основе шаблона [`.env.scheme`](.env.scheme):

```bash
cp .env.scheme .env
```

Заполните переменные (пример):
```env
POSTGRES_USER=postgres
POSTGRES_PASSWORD=postgres
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DATABASE=tictactoe
APP_PORT=8080
```

---

### 2. Запуск через Docker Compose (Рекомендуется)

Запуск приложения вместе с PostgreSQL одной командой:

```bash
docker compose up --build
```

Сервер будет доступен по адресу `http://localhost:8080`.

---

### 3. Локальный запуск (без Docker)

1. Убедитесь, что PostgreSQL запущен и база данных создана.
2. Примените миграции с помощью [goose](https://github.com/pressly/goose):
   ```bash
   make migrate-up
   ```
3. Запустите сервис:
   ```bash
   go run cmd/main.go
   ```

---

### 4. Запуск тестов

Запуск всех тестов проекта:
```bash
make test
# или напрямую:
go test -v -race ./...
```

Генерация отчёта о покрытии тестами:
```bash
make test-cover-html
```

## 📡 Спецификация REST API

Все запросы и ответы используют `Content-Type: application/json`.  
Большинство эндпоинтов игры требуют заголовок авторизации:  
`Authorization: Basic <base64(login:password)>`.

### 👤 Пользователи

#### 1. Регистрация пользователя
* **Метод**: `POST /user/register`
* **Авторизация**: Не требуется
* **Тело запроса**:
  ```json
  {
    "login": "player1",
    "password": "secretpassword"
  }
  ```
* **Ответ**: `201 Created` (`"User registered"`)

#### 2. Проверка аутентификации
* **Метод**: `POST /user/auth`
* **Авторизация**: `Authorization: Basic <base64>`
* **Ответ**: `200 OK` (UUID пользователя в теле)

#### 3. Получение информации о пользователе
* **Метод**: `GET /user/{uuid}`
* **Авторизация**: `Authorization: Basic <base64>`
* **Ответ**: `200 OK`
  ```json
  {
    "id": "e7b0e27a-8b1e-4c7e-97c2-550998f8045f",
    "login": "player1"
  }
  ```

---

### 🎮 Управление игрой

#### 1. Создание новой игры
* **Метод**: `POST /games`
* **Авторизация**: `Authorization: Basic <base64>`
* **Тело запроса**:
  ```json
  {
    "mode": "player_vs_bot"
  }
  ```
  *(Допустимые значения `mode`: `"player_vs_bot"`, `"player_vs_player"`)*
* **Ответ**: `201 Created`
  ```json
  {
    "id": "a988d8b9-8e89-4bc2-9e8d-d790757a3e81",
    "status": "player_turn",
    "active_player": "e7b0e27a-8b1e-4c7e-97c2-550998f8045f",
    "player1_symbol": 0,
    "player2_symbol": 1,
    "winner": -1,
    "board": [
      [-1, -1, -1],
      [-1, -1, -1],
      [-1, -1, -1]
    ]
  }
  ```

#### 2. Получение состояния игры
* **Метод**: `GET /games/{uuid}`
* **Авторизация**: `Authorization: Basic <base64>`
* **Ответ**: `200 OK` (объект `GameBoardResponse`) или `404 Not Found`.

#### 3. Совершение хода
* **Метод**: `POST /game/{uuid}`
* **Авторизация**: `Authorization: Basic <base64>`
* **Тело запроса**:
  ```json
  {
    "board": [
      [0, -1, -1],
      [-1, -1, -1],
      [-1, -1, -1]
    ]
  }
  ```
* **Ответ**: `200 OK`  
  В режиме `player_vs_bot` сервер валидирует ход игрока, сразу вычисляет и делает ответный ход бота и возвращает состояние доски с обоими ходами.  
  В режиме `player_vs_player` возвращает обновлённую доску и передаёт ход второму игроку.
* **Ошибки**: `400 Bad Request` при нарушении правил (не свой ход, изменение старых клеток, несколько ходов).

#### 4. Присоединение к открытой игре (PvP)
* **Метод**: `POST /games/{uuid}/join`
* **Авторизация**: `Authorization: Basic <base64>`
* **Ответ**: `200 OK` (второй игрок регистрируется со статусом `player_turn`).

#### 5. Список открытых игр
* **Метод**: `GET /games`
* **Авторизация**: `Authorization: Basic <base64>`
* **Ответ**: `200 OK` (массив открытых игр, ожидающих второго игрока).

### 📋 Обозначения и состояния

| Значение клетки | Описание |
| :---: | :--- |
| `-1` | Пустая клетка |
| `0`  | Первый игрок (Крестик `X`) |
| `1`  | Второй игрок / Бот (Нолик `O`) |

| Статус игры (`status`) | Описание |
| :--- | :--- |
| `waiting_for_players` | Ожидание подключения второго игрока |
| `player_turn` | Игра активна, ожидается ход активного игрока |
| `player_wins` | Игра завершена победой одного из игроков |
| `draw` | Игра завершена вничью |

| Победитель (`winner`) | Описание |
| :---: | :--- |
| `-1` | Победителя нет (игра продолжается или ничья) |
| `0`  | Победил первый игрок (`X`) |
| `1`  | Победил второй игрок / бот (`O`) |

## 🕹️ Интерактивный веб-клиент

В корень проекта входит легковесный веб-интерфейс [`tic-tac-toe.html`](tic-tac-toe.html):

1. Запустите бэкенд (`docker compose up` или `go run cmd/main.go`).
2. Откройте [`tic-tac-toe.html`](tic-tac-toe.html) в браузере.
3. Введите логин/пароль и нажмите **«Регистрация»** (для создания тестового пользователя).
4. Выберите режим (`Против бота` или `2 игрока`) и нажмите **«Создать»**.
5. Кликайте по клеткам игрового поля для интерактивной игры!

## 🛠️ Стек технологий

- **Язык**: [Go](https://go.dev/) (1.25+)
- **База данных**: [PostgreSQL 16](https://www.postgresql.org/)

- **Контейнеризация**: Docker, Docker Compose
