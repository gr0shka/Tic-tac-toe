# Tic-Tac-Toe AI Service

RESTful API сервис для игры в «Крестики-нолики» с непобедимым соперником на базе алгоритма **Minimax**. Сервис спроектирован в соответствии с принципами **чистой архитектуры (Clean Architecture / DDD)** и современными стандартами разработки на Go.

---

## ✨ Ключевые возможности

- **Непобедимый ИИ (Minimax)**: Интеллектуальный противник с оптимизацией по глубине дерева решений (Depth Penalization), выбирающий быстрейший путь к победе или блокирующий угрозы.
- **Чистая архитектура (DDD)**: Полная изоляция бизнес-логики от деталей доставки и хранения. Соблюдение принципа инверсии зависимостей (DIP).
- **Внедрение зависимостей (DI)**: Сборка графа приложения и управление жизненным циклом (включая Graceful Shutdown HTTP-сервера) через [Uber Fx](https://github.com/uber-go/fx).
- **Многопоточность и сессии**: Поддержка одновременных изолированных игровых сессий, идентифицируемых через UUID.
- **Строгая валидация ходов**: Серверная проверка очередности ходов, запрет на модификацию ранее занятых клеток и множественные ходы.
- **Поддержка `context.Context`**: Сквозной проброс контекста от HTTP-обработчиков до вычислений Minimax с корректной отменой задач при дисконнекте клиентов.
- **Встроенный веб-клиент**: Интерактивный легковесный веб-интерфейс ([`tic-tac-toy.html`](tic-tac-toe.html)) для визуального тестирования API в браузере.

## 🏛️ Архитектура проекта

Проект организован по классической структуре Standard Go Project Layout:

```text
├── cmd/
│   └── main.go                         # Точка входа в приложение
├── internal/
│   ├── domain/                         # Слой бизнес-сущностей и доменных правил (чистый Go)
│   │   ├── game/                       # Модели: GameBoard, CurrentGame, Player, доменные ошибки
│   │   └── service/                    # Доменные сервисы: расчет ходов (Minimax), валидация доски
│   ├── usecase/                        # Слой прикладных сценариев (оркестрация домена и хранилища)
│   │   ├── app.go                      # Интерфейс AppService
│   │   ├── app_impl.go                 # Реализация бизнес-сценариев
│   │   └── repository.go               # Контракт хранилища (DIP)
│   ├── repository/                     # Инфраструктурный слой доступа к данным
│   │   └── mapstore/                   # Потокобезопасное хранилище в памяти (sync.Map) и DTO-мапперы
│   ├── transport/                      # Слой доставки
│   │   └── http/                       # HTTP-хэндлеры, DTO контракты, CORS middleware
│   └── di/                             # Точка сборки зависимостей (Composition Root)
│       └── register.go                 # Регистрация компонентов в Uber Fx и хуки запуска сервера
└── tic-tac-toy.html                    # Веб-клиент для ручного тестирования
```

## 🚀 Быстрый старт

### Требования
- **Go**: `1.22+` (протестировано на `1.25+`)

### Запуск сервиса

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/gr0shka/Tic-tac-toe.git
   cd Tic-tac-toe
   ```

2. Загрузите зависимости:
   ```bash
   go mod download
   ```

3. Запустите HTTP-сервер:
   ```bash
   go run cmd/main.go
   ```
   Сервер запустится на `http://localhost:8080`.

### Запуск тестов

Запуск полного набора модульных тестов (доменная логика, сценарии, хранилище, хэндлеры):
```bash
go test -v ./...
```

## 📡 Спецификация REST API

Все запросы и ответы используют заголовок `Content-Type: application/json`.

### 1. Создание новой игры
* **Метод**: `POST /games`
* **Тело запроса**: отсутствует
* **Успешный ответ**: `200 OK`
  ```json
  {
    "id": "c6c8090c-9ded-4f6e-8dac-52be7711a010",
    "game_is_ended": false,
    "winner": -1,
    "board": [
      [-1, -1, -1],
      [-1, -1, -1],
      [-1, -1, -1]
    ]
  }
  ```

### 2. Получение состояния игры
* **Метод**: `GET /games/{uuid}`
* **Успешный ответ**: `200 OK` (или `404 Not Found`, если игра не найдена)
  ```json
  {
    "id": "c6c8090c-9ded-4f6e-8dac-52be7711a010",
    "game_is_ended": false,
    "winner": -1,
    "board": [
      [0, -1, -1],
      [-1, 1, -1],
      [-1, -1, -1]
    ]
  }
  ```

### 3. Совершение хода
* **Метод**: `POST /game/{uuid}`
* **Тело запроса**:
  ```json
  {
    "board": [
      [0, -1, -1],
      [-1, -1, -1],
      [-1, -1, -1]
    ]
  }
  ```
* **Успешный ответ**: `200 OK` (сервер валидирует ход игрока, делает ответный ход бота и возвращает обновленное состояние):
  ```json
  {
    "id": "c6c8090c-9ded-4f6e-8dac-52be7711a010",
    "game_is_ended": false,
    "winner": -1,
    "board": [
      [0, -1, -1],
      [-1, 1, -1],
      [-1, -1, -1]
    ]
  }
  ```
* **Ошибка валидации**: `400 Bad Request` при нарушении правил игры (например, изменение предыдущих ходов или несколько ходов за раз).

#### Условные обозначения на доске
| Значение | Описание |
| :---: | :--- |
| `-1` | Пустая клетка |
| `0`  | Ход первого игрока (Крестик / Человек) |
| `1`  | Ход второго игрока (Нолик / Бот) |

## 🎮 Веб-клиент

Для комфортной игры с ботом прямо в браузере в репозиторий включен клиент [`tic-tac-toy.html`](tic-tac-toe.html):

1. Запустите бэкенд (`go run cmd/main.go`).
2. Откройте файл [`tic-tac-toy.html`](tic-tac-toe.html) в любом браузере.
3. Нажмите кнопку **Create** для создания игры и делайте ходы по клику на клетки доски.
